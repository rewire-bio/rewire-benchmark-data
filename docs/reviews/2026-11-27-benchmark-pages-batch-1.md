# Benchmark pages, batch 1, 2026-11-27

Prepared by Claude agents. No human review is claimed. Two research agents fetched sources and wrote the content, two agents verified it, one applied their findings, and a separate session checked and applied the result.

## What changed

24 Tier 1 benchmark records gain a `profile`, and 15 of them a `run_guide`. These are the Tier 1 benchmarks without a page that have the most results. The new source records in `batch.jsonl` pin the files the content was written from. No result, evaluation, protocol or claim was added or changed, and no existing attribute was edited.

This is the first batch made with the benchmark form of the page loop (`scripts/enrich/briefs/benchmark-page.md`, `enrich.py --kind benchmark`).

## Sources

The brief asks for the benchmark paper's full text wherever an open copy exists, and 22 of the 24 pages have it, most as NCBI PMC XML. GFMBench-API was written from its repository alone, because the only open copy of its paper is on bioRxiv, which was rate limiting. The ClinGen PP3/BP4 calibration and the rare-disease case tests are Rewire studies and were written from their own repositories.

Every fetched file was kept, whatever its licence, and uploaded to the private archive bucket under the sha256 its source record pins.

## Structured facts

The content files in `specs/` carry a `structured` list: 177 entries, one per task or track, with dataset, size, split rule, metric and direction, addresses and licences, each backed by a copied passage. They are not written to the records in this change. Where a saved file does not give a figure for the exact set an entry describes, the field is null.

## How statements were checked

Every copied passage was confirmed present in its saved file by `scripts/enrich/check_spec.py`. Two verifier agents that had not written the content judged 804 statements against the saved files and raised 38 findings (4.7%): 4 contradicted by a source, 31 that went partly beyond it and 3 with no support. That is about twice the rate of recent model batches. Benchmark pages carry more numbers, and most faults were a number attached to the wrong set: a whole-corpus size on each of its panels, a pairwise comparison's count given as the benchmark's size, a task count that did not match its table. All 38 were applied (37 corrected, 1 removed) and the checker was run again. No page in this batch was read in full by the applying session before merge.

## Found in the benchmarks themselves

- DNALONGBENCH: the CNN training script saves the weights of the best validation epoch (`best_model.pt`) and never loads them. The test score it prints comes from the last epoch's weights. The page says so, with the lines quoted. This was read from the saved script by the verifier and again by the agent that applied the findings; no person has confirmed it.
- Three benchmarks print a different DOI in the paper and in the repository README: the zero-shot RNA language model benchmark, DNALONGBENCH, and Hall and Coin 2024. Each page says which was used.
- Ludaic and Elofsson 2026: the analysis script the README runs is not in the repository, only compiled files.

## Open questions

- CIViC MCP 2026: the record says it is not an executable suite, and the page has a run guide that rescores the saved model outputs. One of the two should change.
- GFMBench-API: the repository address is the one the saved files were fetched from; no saved file prints it.

## Run guides

All have status `source_reviewed_not_executed`. None was run.
