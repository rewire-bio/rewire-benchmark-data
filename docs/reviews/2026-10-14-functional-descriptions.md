# Functional descriptions and provenance notes, 2026-10-14

Issue #88. Change table: `data/omics/qa-descriptions-20261014/corrections.csv`, applied with `npm run records:correct`. Written by a Claude agent; no human review is claimed, and the researched descriptions have not had an independent second review.

## What changed

`npm run records -- descriptions` lists every model, method, pipeline, service and configuration whose description is a placeholder ("Identity as reported in this paper", "Exact source-reported configuration or submission label", "Existing candidate catalogue entry"), carries provenance ("as run in the cited comparison", "quoted from prior work in MIMIC Table S11", "(You et al. 2026 Table 1)", "Cited in the source as ref 18"), or repeats the description of a differently named entity (DELLY and Manta, the BEND baselines, the GeneDisco acquisition functions). On origin/main at b67ec37 it listed 3,965 published records: 3,791 configurations, 74 methods, 73 models, 26 pipelines and 1 service. Excluded records are not published and are not changed.

Each listed record gets a new description, and the text that described where it came from moves to the new attribute `provenance_note`. No other field changes. The old description is kept in the table's `old_value` column and, for configurations, verbatim in `provenance_note`.

| Group | Records | How the new description was written |
| --- | --- | --- |
| Models, methods, pipelines and the AlphaFold 3 Server, new sentences | 101 | From a primary source: the record's own cited paper where it describes the method, otherwise the method's own paper, model card or repository. The URL, locator and a supporting quote for each are in `systems-researched.jsonl` and in the table's `evidence` column. |
| Models and methods with sourced text and a provenance tail | 73 | The functional text already in the description is kept; the locator, citation or "cited in the source as" tail moves to `provenance_note` (`split.py`). |
| Configurations | 3,791 | Generated by `build.py` from the record's own fields: its label, what it configures (`configuration_of`, `uses_model` or `family` links) and its recorded settings (parameters, training setting, representation and head, hyperparameters, reported configuration, checkpoint, version). A configuration with no settings or links is described by the benchmark it was scored in. Leaderboard and challenge entries (1,730) are described by their benchmark, because their labels are free text chosen by participants. |

## Findings while writing the new sentences

- Four BEND records were wrong, not only generic. AWD-LSTM, ResNet-LM, NT-H and NT-MS were described as "baselines trained end to end from one-hot sequence". In BEND they are language models (two trained by the BEND authors, two Nucleotide Transformer checkpoints) scored through frozen embeddings; only the CNN is a one-hot baseline. Their provenance notes say so.
- DART-Eval's "ChromBPNet (ab initio)" used pretrained ENCODE ChromBPNet models, not a model trained from scratch by the DART-Eval authors.
- The new sources used for the researched sentences are recorded in the table's evidence column, not as `source` records with artifact hashes. Vendor pages for Gemini, GPT-5.4, GPT-3.5 Turbo and Claude v1 are live pages retrieved on 2026-10-14.

## Use-case pins

Model, method, pipeline, service and configuration descriptions are not pinned by relevance judgements, summaries or baselines (`judgementPinFields` in `shared/omics/use-cases.ts` pins use cases, protocols, sources, evaluations and results). `npm run use-cases:repin` is not needed, and no judgement is withheld by this change.

## Check

`records -- check` and `records -- add` now reject a placeholder, provenance-style or shared description on these kinds (`shared/omics/descriptions.ts`), so new records need a functional description and put provenance in `provenance_note`.
