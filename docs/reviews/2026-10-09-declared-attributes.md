# Declared attributes, 2026-10-09

Issue #42, stage 3 (requirements R4 and R5). Record attributes were an open bag: 546 kind and key pairs over 28,719 records, with five ways of saying "missing", sixteen uncertainty shapes and seventeen review sub-keys used inconsistently. This change declares every attribute per kind with a type, converts the store to those types, and rejects anything else at intake. An AI-assisted inventory listed every key, its readers and its values; an independent AI review checked the conversion (findings below). No human review is claimed.

## What changes

- `shared/omics/attribute-registry.ts` declares 597 keys over 16 kinds, each with a type from `shared/omics/attributes.ts`: text, integer, decimal string, date, URL, DOI, hash, record IDs, a concept scheme, a structured type (missing metadata, uncertainty, coverage, review, reported population) or `json` for structured payloads with their own validators. `npm run records -- check` and `records -- add` reject undeclared keys, wrong types, nulls, a field that has both a value and a missing reason, and a missing reason for an undeclared field.
- Missing values: 11,494 bare nulls and every free-text marker become one form, `missing_metadata.<field> = {reason, note?}`, with the reason from the new scheme `data/vocab/missingness.ttl`. The five tokens map directly. The 74 free-text strings map through `data/vocab/migration/missingness.csv`, keeping the text as the note. A null with no reason becomes `unextracted`, which claims nothing about the source. Result: 40,211 unreported, 26,923 unextracted, 27 unavailable, 10 inapplicable, 4 conflicting. Every result has either an uncertainty or a reason for its absence.
- Uncertainty: every result uncertainty is absent with a reason or one of five types. 2,167 standard deviations, 67 standard errors, 520 confidence intervals and 268 unresolved spreads; numbers are decimal strings, levels are fractions. Bootstrap summaries keep their separate mean as `center`, so they are not plotted as intervals on the printed value. 362 paper rows that had a value and a stale `inapplicable` marker keep the value.
- Reviews: one shape on 15,429 records. `method` and `reviewer` are always lists, `actor` merges into `reviewer`, `notes` into `note`, a date-only `reviewed_at` becomes `date`, and a `date` that repeats `reviewed_at` is dropped. Source `review_method` and `review_scope` move into `review`.
- Renames: source `locator`, `license`, `code_license`, `article_license` and `sha256` to `source_locator`, `licence`, `code_licence`, `article_licence` and `artifact_sha256`; result `source_printed_cell` to `printed_source_cell`; dataset `scope` to `scope_note`; dataset subset `dataset_id` to `recipe_dataset_id` (these are recipe IDs, not record IDs); `family` on configurations and methods to `family_label` (it held labels such as "pretrained", not family links); configuration `foundation_model` into `foundation_model_eligible`.
- Structure: evaluation `coverage` strings and result coverage become `{scored, eligible, unit, note}`; the two object-valued evaluation `protocol` values split into `protocol`, `protocol_version` and `proposed_protocol_id`; protocol uncertainty notes become `uncertainty_reporting`; protocol `caveats` and `important_limitation` join `limitations`; four structured protocol `procedure` objects move to `protocol_configuration`; five structured dataset `population` objects move to `population_detail`; evaluation `run_url` copies of `reproduction_url` are dropped and site paths become `run_page`.
- Moved, not deleted: `historical_missing_metadata`, `legacy_row`, `legacy_paper`, `legacy_import_source_id`, `acquisition_candidate_id`, `local_cache_path` and `historical_entity_links` from 4,798 records are kept in `data/provenance/moved-attributes.jsonl`.
- Dropped, because the value repeats the kind, the field definition or another record: `metadata_review_scope` (one sentence), `benchmark_applicability` (one sentence), `published_score_reproduction` and `suite_complete` (always false), configuration `reference_kind` (always `not_a_reference`), `entity_level` on kinds where it repeats or contradicts the kind (configuration, dataset, dataset subset, evaluator, pipeline, protocol, task), evaluation `evaluation_group_note` (one sentence), the two `publication_status` copies that equal their source, `method_type` copies of `facets.method_types`, configuration `execution` and evaluation `model_configuration` copies, and result copies of the parent evaluation's `same_paper_experiment_set`, `total_targets`, `missing_count` and `evidence_overlap` (values that differ stay).

28,112 records change. No ID, name, link, source, facet, printed value, numeric value, metric, unit or direction changes. `evidence_experiment_set_id` stays on results although it repeats the evaluation, because 212 claims cite it there.

## Readers and writers

`normalizeAttributes` is the only conversion: the migration (`npm run attributes:migrate`) and every reader (`shared/omics/current.ts`, used wherever snapshots load) apply it, so archived releases read the same as new ones. Strict checks run on the store, not on archived releases. Profile enrichment no longer renames `missing_metadata`. Importers convert new batches with `npm run attributes:migrate -- --batch <file>` before review; the two Python run importers no longer write the dropped keys and write coverage as an object. The website reads the new shapes through rewire-bio/rewire-database#126, which must merge first.

Not in this change (stage 3b): exporting every declared attribute to RDF with its datatype and structured uncertainty as a node, per-kind SHACL shapes generated from the registry, and running SHACL at `records -- add`.

## Independent review

An independent AI review compared all 28,719 records with the store before the migration, checked every non-null uncertainty (28 old shapes) rather than a sample, and checked each row of the missing-reason table.

- It found that 5,328 results whose uncertainty was a bare null lost the key without gaining a reason. Fixed: a null uncertainty now becomes `unextracted`, and the migration was rerun from the original store.
- It proposed eight changes to `missingness.csv`, all applied. "Not estimated; one (complete) selected evaluation" moves from inapplicable to unreported, since uncertainty applies to those estimates and the runs did not compute it. "Endpoint-specific weighting in source where noted" moves to unextracted. Five notes that say the source does not state the value move to unreported.
- It confirmed that no number, bound, level, sample size or resample count was lost or altered. Bootstrap summaries were not turned into confidence intervals, and unresolved spreads were not upgraded to standard deviations.
- It confirmed that every moved value in `moved-attributes.jsonl` is byte-identical to the original, and that every drop is an exact copy or one of the documented constants.
