The contested-results checker compares what different papers report about the same two models. This version changes what it counts and how it labels what it finds, so it stops flagging differences that come from comparing different tasks, different model sizes or the same benchmark twice.

1. The idea in plain terms

Every release, the checker asks one question for each pair of models: do the papers that tested both of them agree on which is better? If one paper says the opposite of the others, it flags that paper's result as contested, as a lead for us to look into.

That question only makes sense if the papers were measuring the same thing. Version 3 doesn't check that carefully enough. Version 4 adds four checks before it compares anything.

Words used in this document

System
A model or method you could run: ESM-2 650M, or "union of Mutect2, Strelka2 and DeepSomatic". A configuration is one recorded setup of a system.
Study
One independent piece of work: a paper with its supplement, code and leaderboard files.
Comparison
Two systems scored on the same protocol, dataset and metric in one study. One study usually has many.
Verdict
A study's overall answer for a pair: A is better, B is better, or split. New in v4.
Task scope
Whether the studies being compared measured the same task, different tasks, or we can't tell because links are missing.
Outlier finding
Three or more studies have a verdict, and one disagrees with the others.
Two-study conflict
Only two studies have a verdict, and they disagree. Neither is called the outlier. New in v4.
Listing
Whether a finding shows on the public contested page, or only on the "needs review" list. New in v4.

4. Rule changes

All in scripts/kg/contradictions.py. New thresholds go in data/ontology/discrepancy-rules.json, which moves to version 4.

4.1 Resolve systems

  • Index.identity(): a configuration with a combination_rule resolves to itself, not to its configuration_of target. Two combined configurations compare as one system only if they are the same record.
  • New Index.members(system): the resolved uses_model targets of a combined configuration.
  • comparisons() skips a pair where one system is combined and the other is one of its members.

4.2 Group into studies

  • Index._studies() also unions a source with its companion_of target. Study keys (_study_keys) are unchanged: lowest DOI first, so a merged ProteinGym study keeps the paper's DOI key.

4.3 One configuration per system per study

  • New first pass in comparisons(): for each (study, resolved system), count results per tested configuration and choose one: most results, then the larger model size, then the configuration ID. The size is read from the configuration's name, model version, checkpoint or reported name (650M, 1.6B, 15 billion); the parameters attribute holds settings, not sizes.
  • The second pass keeps only the chosen configuration's rows. Within a group, if the chosen configuration has several rows, the best value is still used, as today; this case is rare because qualifier and split are already in the group key.
  • Comparison gains config_a and config_b.

7. IDs and migration

  • Outlier findings keep today's key, {rule, systems, anchor, metric, outlier_study}, so their IDs only change if their systems do (combined configurations) or their outlier study's key does.
  • Two-study conflicts use {rule: "two-study-conflict", systems, anchor: null, metric: null, studies: [key1, key2]} with the two study keys sorted.
  • Migration script (new, scripts/kg/migrate-discrepancy-ids.py): derives the v4 findings, and for each review claim whose finding stopped firing, finds the one new ordering finding of the same two systems that includes the old outlier study (looked up in the previous release's discrepancies.json). It writes the next claim revision with the new ID, the old one in previous_ids, and the same state and rationale, plus a table of every decision.
  • One chain per new finding. Two old IDs cannot both be forwarded to one new finding: their revision 1 claims would collide. So when the ESM3/ProteinMPNN mirrors (f82ed80f, fed245c4) became one conflict, one chain was carried forward and the other, already explained, retired as a resolved finding. The script fails if the one left behind is unsettled.
  • What happened (data/omics/discrepancy-review-20261024-rules-v4-migration/): four claims carried forward, #210 (4db3e5d2, investigating), #209 (8c69346a), ESM-IF1/ProteinMPNN (d7349300) and ESM3/ProteinMPNN (f82ed80f). #211 kept its ID. The two false positives, both Geneformer/scGPT findings and Mutect2/Octopus stopped firing and are kept as resolved findings.

10. Open questions

QuestionProposed answer
Four studies split two against two: is that a finding?Not in v4. Report the count at release so we know how often it happens.
"Most results" may pick a small model a study only used for ablations.Accept for v4. If the release review shows bad picks, add an optional headline flag on configurations.
Alavi passes the verdict threshold at exactly 75% (9 of 12).Keep 75%. The labelled-findings check fails the release if it drops out, so a change to the threshold has to be deliberate.
Who owns the website's contested page?To confirm. Step 4 depends on it.
A same-task verdict can pool other tasks: Wang 2026 gives one verdict over structure, classification and fitness, though only fitness shares the RNAGym task.Next refinement: compute verdicts per shared task when the two sides overlap on only some of their assessments.
Almost every finding is low, because 123 of 126 have unreviewed identity links.Expected. Review the configuration links of the findings worth raising; do not loosen the rules for them.
